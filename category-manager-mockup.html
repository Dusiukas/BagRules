What this flow changes

  • Simple filters, no logic wordsThe default rule editor is one row per item property (kind, quality, binding, slot, name), each a dropdown. A plain sentence above says what the category catches. The and/or/not builder moves to Advanced for those who want it.
  • Create from an itemDrop an item on the manager and the new category is pre-filled from it: type, subtype, quality and name as tick boxes, with the matching bag items shown before you create anything.
  • Pin by droppingDrop an item on a category row to pin it there. Pinned items show as removable chips under Advanced, replacing the typed item-ID box.
  • Template gallery"+ New" opens ready-made categories with a live count of what each would catch in your bags. One click adds it, already enabled.
  • Names, not IDsConditions say "Item type is Consumable" and "Item subtype is Trade Goods: Cloth" instead of class 0 and subclass 5.
  • Conflicts you can see and fixPriority is Low to Highest instead of a number. When another category takes an item, the preview says which one and offers "Make this one win". Try it on Weapons.
  • Uncategorised inbox and "why is this here"The list ends with the items no rule catches, each one click away from a new category. Hovering a bag item names the category that caught it.
